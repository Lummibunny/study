## 0. 总结

用**国网真实的充电订单 + 用户评论数据**（山东临沂，28,306 条订单 / 508 个用户 / 241 个充电站），先用一个非常粗糙的**正负情感词表**把文本评论转成数字评分，再用 **LightGBM** 预测每个用户对每笔订单的评分，**顺手把 LightGBM 输出的特征重要性（Fi）当成"这个用户看重什么"的偏好画像**；然后用 Fi 加权构造**用户-充电站共现矩阵**，用 **SVD** 分解后预测用户对未去过站点的潜在评分，排序输出 Top-N 推荐。最终 F1 = 0.5527，比传统 ItemCF + 充电次数的方法**提升 96%**。

## 2. 研究背景与动机

 2.1 现实背景（中国数据）
中国新能源汽车保有量，电动汽车总用电量，中国充电桩总量（公共桩、私人桩）

**作者指出的核心问题**：
1. **充电站建设与电动汽车数量之间的不平衡**，是制约 EV 普及的关键因素之一 。
2. 虽然桩的总量"看起来够"，但**EV 的普及度和车主的充电服务体验仍有很大提升空间**。
3. 个性化充电站推荐意义重大 

2.2 个性化推荐的三重价值
一个有效的个性化 EVCS 推荐，会考虑用户偏好带来的**不确定性**（等待时间、充电成本、行驶距离），并产生三重效果：
- 帮助用户自主作出充电决策；
- 提高充电站利用率，优化充电设施配置；
- 促进 EV 产业可持续发展

 2.3 立论支点：评论数据被忽视了

> "用户评论是 EV 充电用户基于自身体验产生的**主观数据**，能真实反映用户偏好、洞察用户需求。**但在现有的 EVCS 推荐研究中，缺乏对用户评论数据的深入分析。**"

这是本文挖到的 Gap——和第二篇（Lv 2025 用 PlugShare 评论研究 EV 采纳）**是同一个洞察**，但应用场景不同：
- Lv 2025：评论 → 解释**宏观的 EV 采纳率**（州级，空间计量）
- **本文：评论 → 驱动**微观的个性化推荐（用户级，机器学习）

## 4. 研究方法

### 4.0 总体流程（Figure 1）

```
原始历史充电订单 + 充电站服务信息
        ↓
【1 样本构建】数据预处理（缺失值 / 空值 / 异常值 / 重复记录）
        ↓  筛选：充电次数 > N？—— 否 → 剔除
        ↓  特征工程（订单视角 + 站点服务视角）
【2 用户评分预测】评论文本 → 数值化 → LightGBM 预测评分
        ↓  输出：预测评分 + 特征重要性 Fi（= 用户偏好画像）
【3 充电站推荐】用 Fi 构建用户-电站共现矩阵 U → SVD 分解 → 预测评分 → 排序
        ↓
输出 Top-N 推荐列表
```
样本构建——用户评分预测 + 偏好提取——
### 4.1 阶段一：样本构建

**原始数据字段**：用户编码、充电开始时间、充电费用、充电站 ID、用户评分（文本形式）。

**预处理**：处理缺失值、异常值、重复记录。

**样本筛选标准（两条硬门槛）**：
1. 至少有 **1 条非空**的充电订单评论；
2. 充电交易次数 **> 30 次**。

> 理由：评分预测需要一定数据量才能学习；评论是本文的核心信息来源，没有评论的订单无法构造标签。

**筛选后样本**：
- **28,306 条**交易记录
- **508 个用户**
- **241 个充电站**
- 地域：**中国山东省临沂市**（Linyi, Shandong）

**特征工程：17 个特征**
- **14 个普通特征**（Figure 2 热力图展示）
- **3 个多分类特征**：充电方式（charging method）、订单来源（order source）、交易结束原因（reason for transaction ending）

特征从**两个视角**构造：

| 视角 | 内容 |
|---|---|
| 用户充电订单 | 反映用户历史行为 |
| 充电站服务 | 包含充电站的多维服务特征 |

### 4.2 阶段二：用户评分预测 + 偏好提取（LightGBM）

#### (1) 把文本评论转成数字评分（**本文最薄弱的一环，务必看清**）

原始评分是文本形式，无法直接预测。作者的做法是**极简的词表计数法**：

- 把评论文本中的词分为**正向词**和**负向词**
- **8 个正向词**，每个 **+1 分**
- **20 个负向词**，每个 **−1 分**
- **评论为空 → 记 0 分**
- 每笔订单的用户评分 = 词表命中计分之和

**Table 2 完整词表**（这个表很有价值，是充电场景的专属情感词典）：

| 正向词（+1，共 8 个） | 负向词（−1，共 20 个） | | |
|---|---|---|---|
| No queuing（不用排队） | Wrong price（价格错误） | Slow charging（充电慢） | Abnormal stop（异常停止） |
| Affordable price（价格实惠） | High price（价格高） | Occupy a large space（占地面积大） | Slow QR code scanning（扫码慢） |
| Free parking（免费停车） | Wrong location（位置错误） | Startup failure（启动失败） | Incomplete guidance（指引不完整） |
| Fast charging（充电快） | Poor charging experience（充电体验差） | No navigation（无导航） | Long queuing time（排队时间长） |
| Enough charging piles（桩位充足） | Faulty piles（故障桩） | Unable to charge（无法充电） | |
| Accurate navigation（导航准确） | General environment（环境一般） | Poor environment（环境差） | |
| Fast QR code scanning（扫码快） | Equipment failure（设备故障） | Need to wait（需要等待） | |
| Good environment（环境好） | Frequent connector error（频繁枪错误） | Unable to pull out connector（枪拔不出） | |

> **我的评价（重要）**：这个转换方法**非常粗糙**。它有三个明显问题：①只看词频不看语义强度（"充电慢"和"设备故障"权重相同）；②没有否定词处理（"没有排队时间"可能被误判）；③**把"空评论"记作 0，与"中性评价"混淆**——这在后文直接导致了严重的数据不平衡（89.4% 的订单评分为 0）。**这正是你可以改进的地方**（见第 11 节）。

#### (2) LightGBM 模型（3.1 节）

**LightGBM 是什么**：基于 **GBDT（梯度提升决策树）**的梯度提升算法 [35]（Ke et al., NeurIPS 2017）。

**三个关键机制**：
1. **直方图（Histogram）构造**：高效处理数据，把连续特征离散成 bin
2. **拟合残差**：逐步提升弱学习器性能
3. **Leaf-wise（按叶子）生长策略**：限制树深，迭代训练时**只分裂增益最大的节点**，从而降低误差、提升精度与速度

**Algorithm 1 伪代码（直方图算法）逐行解读**：

```
输入：I = 训练数据，d = 最大树深，m = 特征维度
 1. nodeSet ← {0}                        # 当前层的树节点
 2. for i = 1 to d:                      # 逐层递归分裂
 3.   for node in nodeSet:
 4.     usedRows ← rowSet[node]          # 该节点的数据索引
 5.     for k = 1 to m:                  # 遍历每个特征
 6.       H ← new Histogram()            # 建直方图
 7.       for j in useRows:
 8.         bin ← I.f[k][j].bin          # 取该样本在该特征上的分箱
 9.         H[bin].y += I.y[j]           # 累加目标值
10.         H[bin].n += 1                # 累加样本数
11.       在直方图 H 上找最优切分点
12.       gain, split ← EvaluateSplit(H)
13.       if gain > best_gain:
14.         best_gain, best_feature, best_split ← gain, k, split
15.       feature_importance[best_feature] += best_gain   # ★ 累积特征重要性
16.     left, right ← SplitNode(...)      # 分裂节点
17.     nodeSet ← nodeSet ∪ {left, right}
18. predictions ← 每个叶节点内目标值的均值
输出：predictions, feature_importance
```

> **★ 第 15 行是全文的枢纽**：LightGBM 输出的 `feature_importance` **不只是副产品，而是被直接当作"用户偏好画像"**。这是本文方法设计上最巧妙（也最值得商榷）的一步——**用一个预测模型的可解释性输出，去反推"这个用户在意什么"**。

### 4.3 阶段三：充电站推荐（SVD + 共现矩阵）

#### (1) 先说基线：ItemCF（3.2 节，本文的对照方法）

协同过滤分 **UserCF**（基于用户相似度）和 **ItemCF**（基于物品相似度）。

**本文为何选 ItemCF**：因为数据里每个用户都有 **> N 次**充电，数据充足，足以分析用户兴趣变化。

**ItemCF 四步**：
1. 基于历史订单构造 **m×n 共现矩阵 U**（m 用户、n 充电站），`u_mn` = 用户 m 去充电站 n 的**次数**
2. 计算 U 的两两**列向量余弦相似度** `cos(i,j) = i·j / (‖i‖‖j‖)`，构造 **n×n 物品相似度矩阵 Γ**
3. 基于 Γ，为目标用户的历史行为中的每个站点找 **Top-k 相似站点**，形成相似物品集 ψ
4. 按相似度分数排序 ψ 中的物品，生成最终推荐列表

> **ItemCF 的致命弱点（也是本文要打的靶子）**：共现矩阵里只有"去过几次"，**完全不含偏好信息**——去 10 次可能因为离公司近，不代表喜欢。

#### (2) SVD 方法（3.3 节，本文主方法）

**为什么用 SVD 而不是普通协同过滤**：**泛化能力强、空间复杂度低、可扩展性与灵活性更好**。

**Step 1：用 Fi（特征重要性）构造共现矩阵**

- 对某个用户，某笔订单的**偏好得分**：`P = Σ (Fi × i)`
  （即：该订单各特征的值 i，用 LightGBM 给出的特征重要性 Fi 加权求和）
- 把该用户在**同一充电站**的所有订单偏好得分**加总**，作为用户-充电站共现矩阵 U 的一个元素。

> 这一步是本文的**第二个枢纽**：ItemCF 的矩阵元素是"次数"，本文的矩阵元素是 **"用个人偏好权重加权后的得分"**。**矩阵从"行为频次"升级为"偏好强度"**，这就是后面 96% 提升的来源。

**Step 2：SVD 分解**

原文公式（2）：
```
U = R Σ V^T
```

> **⚠️ 原文的符号与维度描述有瑕疵，我按原文照录并标注问题**：
> 原文说"U 是维度 m×k 的用户身份矩阵，m 是用户数、k 是特征数；Σ 是 k×k 的奇异值对角矩阵；V 是 n×k 的充电站身份矩阵，n 是站点数"。
> **问题**：①如果 U 在左边是 m×n 的共现矩阵，分解后应是 `U = R Σ V^T` 且 R 为 m×k、V 为 **n×k**（则 V^T 为 k×n），这样 R(m×k)·Σ(k×k)·V^T(k×n) = m×n 才成立；原文把 V 说成 n×k 时，V^T 的维度就对不上了。②符号 R、V 与常规 SVD 记号（U、Σ、V^T）混用，**U 既指共现矩阵又指"用户特征矩阵"**。
> **写论文时不要照抄这套记号**，用标准写法：`A = U_k Σ_k V_k^T`（A 为 m×n 共现矩阵）。

**Step 3：预测最终评分**

原文公式（3）：
```
Û_i,j = R_i · Σ · V_j^T
```
- `Û_i,j`：用户 i 对充电站 j 的**预测评分**
- `R_i`：用户 i 在特征矩阵中的行向量
- `V_j^T`：充电站 j 在特征矩阵中的列向量

**Step 4：排序取 Top-N**

把 SVD 预测分数从高到低排序，取 **Top-N** 个充电站作为推荐结果。

### 5.1 数据（4.1 节）

| 项 | 数值 |
|---|---|
| 地域 | 中国山东省临沂市 |

### 5.2 实验设置

#### (1) 用户评分预测（4.2.1）

- **划分**：80% 训练 / 20% 测试
- **分层抽样（stratified sampling）**：因为大部分评分为 0，用分层抽样保证两个集合都包含不同评分的样本
- **对比模型**：LightGBM / XGBoost / Random Forest
- **参数（Table 3）**：

| 参数 | LightGBM | XGBoost | Random Forest |
|---|---|---|---|
| Learning_Rate | 0.01 | 0.01 | 0.01 |
| N_Estimators | 200 | 200 | 200 |
| Max_Depth | 10 | 10 | 10 |
| Random_State | 42 | 42 | 42 |
| Min_Samples_Split | — | — | 2 |
| Min_Samples_Leaf | — | — | 1 |
| Sample_Weight | (0,1,2) | (0,1,2) | (0,1,2) |

> **注意 Sample_Weight (0,1,2)**：这正是后文用来处理数据不平衡的**类别权重**设置——非零样本被赋予更大权重。

#### (2) 充电站推荐（4.2.2）

- **划分：按时间顺序（chronological order）**——每个用户**前 80%** 的数据作为训练集，**后 20%** 作为测试集。
  > 这个做法比评分预测阶段的随机划分**更合理**，符合推荐系统的真实场景（用历史预测未来）。**你写论文时可以学这一点。**
- **相似度度量**：SVD 分解后计算充电站之间的**余弦相似度**，取最相似的站作为推荐。
- **超参数搜索范围**：
  - **K（SVD 分解维度）**：50 ~ 200
  - **N（推荐列表长度）**：1 ~ 10
- **基线**：ItemCF（用"用户在某站的充电次数"作为共现矩阵元素）

#### (3) 评价指标（4.2.3）

**回归指标（4 个，评评分预测）**：

| 指标 | 公式 |
|---|---|
| MSE | `(1/n) Σ (y_i − ŷ_i)²` |
| MAE | `(1/n) Σ |y_i − ŷ_i|` |
| RMSE | `√[(1/n) Σ (y_i − ŷ_i)²]` |
| R² | `1 − Σ(y_i − ŷ_i)² / Σ(y_i − ȳ)²` |

**分类指标（3 个，评推荐效果）**：

| 指标 | 公式 |
|---|---|
| Precision | `TP / (TP + FP)` |
| Recall | `TP / (TP + FN)` |
| F1 | `2 × Precision × Recall / (Precision + Recall)` |

其中：
- **TP**：模型正确预测为用户感兴趣的充电站数
- **FP**：模型预测为感兴趣、实际不感兴趣
- **FN**：模型没预测为感兴趣、实际感兴趣

### 5.3 实验结果

#### 结果 1：用户评分预测（4.3.1）

三个模型对比（Figure 4 散点图 + Figure 5 指标柱状图）：

- 理想预测落在**对角线**上（实际分 = 预测分）。
- **三个模型都不同程度偏离对角线**，部分用户评分预测很差。
- **LightGBM 在对角线附近的点最集中**，显著优于 Random Forest 和 XGBoost。

**具体指标（LightGBM 最优）**：

| 指标 | LightGBM |
|---|---|
| **MSE** | **0.9446**（最低） |
| **MAE** | **0.2969**（最低） |
| **RMSE** | 未单独列出数值（图中） |
| **R²** | **0.2935**（最高） |

> **⚠️ 理性看待 R² = 0.2935**：这意味着模型只解释了评分变异的 **29%**，**预测性能其实相当弱**。作者自己在 4.3.4 节也承认了这一点并给了原因。**这是本文最大的软肋，也是你最容易改进的地方。**

结论：后续分析全部基于 **LightGBM** 构建的评分预测模型。

#### 结果 2：用户偏好学习（4.3.2）

**总体特征重要性（Figure 6）**——预测用户评分时最重要的 5 个特征：

| 排名 | 特征 | 含义 |
|---|---|---|
| 1 | **charging time** | 充电时长 |
| 2 | **transaction amount** | 交易金额 |
| 3 | **transaction power** | 交易电量（充电度数） |
| 4 | **offer amount** | 优惠金额 |
| 5 | **reason for transaction end** | 交易结束原因 |

**影响最小的 4 个特征**：
- free parking（免费停车）
- charging method（充电方式）
- excessive code scanning times（扫码次数过多）
- whether charging occurs during peak or off-peak hours（是否峰谷时段充电）

**作者给出的解释**：这些特征可能对用户行为有一定影响，但对评分预测贡献有限，原因可能是**用户对这些因素不敏感**，或**它们在评分上变异太小**。

**关键发现：偏好是因人而异的（这是本文存在的核心理由）**

| 用户群体 | 数量 | 占比 | 情况 |
|---|---|---|---|
| **所有特征重要性都为 0 的用户** | **304** | **59.8%** | 无法从评分预测中推断其充电偏好 |
| **识别出个性化偏好的用户** | **204** | **40.2%** | 通过特征重要性分析识别出个性化偏好 |

> **⚠️ 这是本文第二个大软肋**：**近 60% 的用户，模型完全学不出偏好**。作者在 4.3.4 解释：这 304 个用户中，**95.24% 的订单评分为 0**，极度不平衡掩盖了特征的真实贡献。

**两个具体的个性化偏好案例（Figure 7）**：

| 用户 | 最重要特征 | 原因 |
|---|---|---|
| **User 100266869** | **fault score（故障分）** | 过去 6 个月充电 **78 次**，其中 **16 笔**交易因充电站或充电桩故障而终止 → 故障成为预测其评分的关键因素 |
| **User 107935466** | **charge time（充电时长）** | 平均充电时长 **81 分钟**，显著高于全体平均的 **42 分钟** → 时长成为其偏好预测的关键 |

> 这两个例子很好地说明了本文的**立意**：同样是打分，有人在意"别坏桩"，有人在意"充得快"。

#### 结果 3：充电站推荐（4.3.3）

##### 超参数选择

**K（SVD 分解维度，50–200，Figure 8）**：
- K 在 **50~90** 区间时，accuracy、recall、F1 **显著提升**
- **K > 90 后 F1 趋于稳定**
- **最优 K = 160**

> **⚠️ 我的质疑**：样本只有 508 个用户 × 241 个充电站，共现矩阵的秩最多是 **min(508, 241) = 241**。取 K = 160 相当于保留了 **66% 的秩**，这**几乎谈不上降维**，SVD 在这里更像是"矩阵补全/平滑"而非"隐因子提取"。**这是一个可以写进 related work 批评、也可以自己改进的点**（比如把 K 的搜索上限设为更合理的值，或换成 ALS / 非负矩阵分解）。

**N（推荐列表长度，1–10，Figure 9）**：
- N 在 **1~4** 时 recall **大幅提升**
- N > 5 后性能继续提升但**幅度很小**
- 综合**计算效率与实际应用**，最终选 **N = 5**

##### 推荐结果示例（Table 4，N=5）

| 用户 | 推荐的充电站及预测得分 |
|---|---|
| User 1 | (21, **3.66**), (132, **3.57**), (78, 1.91), (182, 1.24), (120, 0.85) |
| User 2 | (12, **4.19**), (200, **4.07**), (198, 1.88), (78, 1.86), (15, 1.43) |
| User 3 | (106, **14.28**), (231, 3.69), (175, 1.42), (123, 1.07), (24, 0.32) |

> **⚠️ 注意 User 3 的第一个得分 14.28**，与其他得分不在一个量级。这暗示 SVD 预测的分数**未做归一化/裁剪**，可能存在异常值问题。原文未解释。

##### 四个模型对比（Figure 10）——本文的**核心结论**

构造了 **2（推荐方法）× 2（偏好来源）** 共 4 个模型：

| 模型 | 共现矩阵元素来源 | 推荐方法 |
|---|---|---|
| **SVD + LightGBM**（本文） | **LightGBM 特征重要性 Fi 加权得分** | **SVD** |
| SVD + ChargeCount | 充电次数 | SVD |
| ItemCF + LightGBM | LightGBM 特征重要性 Fi 加权得分 | ItemCF |
| ItemCF + ChargeCount（传统基线） | 充电次数 | ItemCF |

**本文模型的最优成绩**：

| 指标 | 数值 |
|---|---|
| **Precision** | **0.5604** |
| **Recall** | **0.6040** |
| **F1** | **0.5527** |

**两条对比结论（这是全文最重要的两句话）**：

1. **SVD > ItemCF**：SVD+LightGBM 和 SVD+ChargeCount 的 recall、accuracy、F1 都**分别高于** ItemCF+LightGBM 和 ItemCF+ChargeCount。
   → 说明 **SVD 在捕捉"用户充电偏好与充电站特征之间的潜在关系"上比 ItemCF 更有效**。
2. **LightGBM > ChargeCount**：SVD+LightGBM 和 ItemCF+LightGBM 的指标都**分别高于** SVD+ChargeCount 和 ItemCF+ChargeCount。
   → 说明 **LightGBM 在识别用户充电偏好上有优势**。

**总体提升**：相比其他方法，混合模型的 **F1 提升 15%~96%**；相比**传统的基于充电次数的 ItemCF 方法，F1 提升 96%**。

> 这个 2×2 的**消融实验设计（ablation design）非常干净**，值得你直接模仿：把"方法"和"输入"各设两个水平，就能同时证明两个贡献各自成立。

### 5.4 讨论（4.3.4，作者很诚实的一节）

#### 问题 1：为什么评分预测这么差？——数据极度不平衡

- 28,306 条订单中，**25,308 条评分为 0**（89.4%）
- 后果：模型训练时**主要见到负样本（评分 0）**，忽略正样本（非 0 评分）相关的特征与模式
- 极端后果：模型可能**干脆把所有评分都预测成 0** 以最小化误差
- **举例**：某用户 A 有 50 笔订单，48 笔评分为 0，只有 2 笔评分为 2 和 5 → 该用户的评分预测模型 **accuracy = 0.96，但 recall 只有 0.05，F1 只有 0.09**

> 这是典型的"**准确率陷阱**"——**accuracy 高但 recall 极低**。你写论文时必须同时报告 precision/recall/F1，就是这个道理。

#### 问题 2：为什么 304 个用户所有特征重要性都是 0？

- 这 304 个用户中，**95.24% 的订单评分为 0**
- 极度不平衡**掩盖了特征的实际贡献**，因为模型主要从非 0 样本中学习
- 结果：0 值样本无法充分反映其影响，导致**部分特征重要性被低估**

#### 解决方案与效果（Figure 11）

**两个手段**：
1. **过采样（oversampling）**：对用户的订单数据进行过采样
2. **调整算法权重**：让算法更重视非 0 样本（即 Table 3 的 `Sample_Weight (0,1,2)`）

**效果**：
- MSE、MAE、RMSE **略有下降**
- **R² 显著提升**
- 后续推荐结果的 **F1 也提升**

> 但作者只说"略有改善 / 显著提升"，**没有给出具体数值**，这是一个报告不完整的瑕疵。

#### 问题 3：用户偏好会随时间变化吗？（增量学习实验）

**实验设计**：
- 把每个用户的**前 30 笔**充电订单输入预测模型作为**基线**
- 之后**每增加一笔订单**，就重新输出一次特征重要性（**增量学习**）

**结果（Figure 12）**：
- **Figure 12a**：特征重要性的**整体标准差非常小**，大部分偏差集中在 **[0, 0.009]** 区间
- **Figure 12b**（取特征重要性变化最大的那个用户）：随着订单增加有小幅波动，但**整体趋势稳定**

**动态推荐实验**：
- 用变化中的偏好做动态 EVCS 推荐
- **结果：每个用户的 Top-5 推荐结果保持不变**

**作者的诚实结论**：
> 虽然数据存在动态变化，但**数据收集的时间跨度不够长**，不足以让充电偏好学习对最终推荐结果产生显著影响。**更长的 time span 留待未来研究。**

> **评价**：这是一个**负结果（negative result）**，但作者如实报告了，还解释了原因。**这种写法是加分的**——很多论文会悄悄把负结果藏起来。

#### 问题 4：计算复杂度

- 模型扩展到**大规模数据集或实时应用**时，特征提取、训练、预测**资源密集**；
- LightGBM 虽然对大规模数据有效，但在**高度不平衡数据集**上仍面临**训练时间与内存消耗**挑战；
- 未来可探索**分布式计算、模型剪枝**等优化手段。

## 6. 结论（第 5 节，逐条）

1. 开发了集成 **LightGBM + SVD** 的混合模型，用历史充电订单和评论数据解决"用户充电偏好学习 + 智能 EVCS 推荐"问题。
2. **LightGBM 在学习用户充电偏好上有效**：能从历史订单中提取复杂信息，显著提升预测精度，并提供**差异化的用户充电偏好数据**。
3. **SVD 能有效捕捉用户与充电站之间的潜在关系**。
4. **SVD + LightGBM 在 precision、recall、F1 上都优于其他模型，F1 提升 15%~96%**，个性化推荐准确性显著增强。
5. 用**过采样 + 算法权重调整**处理数据不平衡，用**增量学习**处理偏好时变。
6. 结论：数据不平衡处理**能改善**推荐结果；而学到的**时变偏好对推荐结果无显著影响**（归因于数据时间跨度短）。

### 11.2 你可以直接改进的点（从弱到强排序）

| 优先级 | 改进点 | 具体怎么做 | 难度 |
|---|---|---|---|
| **★★★★★** | **情感打分太粗糙** | 把 ±1 词表换成**预训练情感模型**（如 BERT/RoBERTa 微调，或中文的 SnowNLP/ERNIE），或用 **LDA 提属性 + 属性级情感**（第二篇 Lv 2025 的做法）。再把"空评论"从 0 改为**缺失值单独处理**（如只用有评论的订单做训练集，或用半监督） | 低—中 |
| **★★★★★** | **R² 只有 0.2935** | ①扩特征（天气、时段、站点周边 POI、历史排队时长）；②用**回归 + 分类两阶段**（先判"是否有评价"，再判"好评/差评"）；③换模型（CatBoost、深度模型） | 中 |
| **★★★★☆** | **60% 用户学不出偏好** | 这是"**行为异质性**"的天然入口。可以把用户先**聚类分群**（K-means 按行为特征），群内共享偏好；或引入**层次贝叶斯** | 中 |
| **★★★★☆** | **接决策理论（你导师方向）** | 文献 [34]（Hu et al., TR-C 2019）已经用**累积前景理论（CPT）**建模 EV 用户的充电行为与风险态度。**你可以把 CPT 的价值函数嵌入推荐排序**：不直接用 SVD 预测分排序，而是把"等待时长/价格/故障率"映射为前景价值再排序。这从"机器学习论文"升级为"**行为决策 + 推荐**"，层次立刻不同 | 中—高 |
| **★★★☆☆** | **时变偏好（作者没做成）** | 作者因为时间跨度短失败了。如果你能拿到**更长跨度数据**，用**时间序列分析 / 滑动窗口 / 遗忘因子**做动态偏好，就是干净的增量贡献 | 中 |
| **★★★☆☆** | **SVD 的降维设定与基线** | K 上限设成合理值；补上 **ALS、NMF、神经协同过滤（NCF）、图神经网络**等基线，让 96% 的提升更可信 | 低 |
| **★★★☆☆** | **与"预约"结合（你的题眼）** | 本文是"**推荐哪个桩**"，你的方向是"**预约机制**"。可以把两者接起来：**先按用户偏好推荐候选桩 → 再在候选集上做预约分配/定价**。这样既继承本文方法，又落回导师给的方向 | 中—高 |
| **★★☆☆☆** | **公平性 / 系统目标** | 个性化推荐会让大家挤向同一批"好评桩"，加剧排队。可以加一个**系统层面的均衡约束**（类似第一篇 Zhang 2025 的调度思路），做"用户满意度 + 系统负载"双目标 | 高 |
