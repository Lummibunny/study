# WorkBuddy 手机端 ↔ 电脑端互通配置手册

> 目标：手机（App / 小程序）新建的任务与产出的 md，自动落进本机 `~/Documents/study` 资源库，并随既有 automation 推到 GitHub。
> 本机环境：WorkBuddy PC **5.3.8**（macOS）｜ 资源库 `/Users/yang/Documents/study`（git：`origin → Lummibunny/study`）

---

## 一、为什么两边不同步（根因）

**同一账号 ≠ 同一个执行地点。**

手机端如果没有「连接这台电脑」，任务是在**云端沙箱**里跑的，产物写在云端的临时工作区；而 `~/Documents/study` 是这台 Mac 上的本地文件夹。两者是两个物理隔离的抽屉，账号相同也不互通——这与早期「多端不同步」的成因一致（各自设备各自存储）。

好消息：官方已于 **2026-08-11** 上线多端同步，**PC ≥ 5.3.8 + App ≥ 1.2.0** 即支持任务、对话记录、产物的三端同步。你这边的 PC 版本刚好达标。

**关键认知**：真正解决「产物回不到 study」的不是同步功能本身，而是——**让手机端的任务跑在这台 Mac 上**。任务由本机 Agent 执行，md 就会直接写进本地文件夹，同步问题从根上消失。

前提，**电脑必须开机且 WorkBuddy 在运行**（远程授权、任务执行都依赖它在线）。

---

## 二、操作步骤与验证标准

| # | 步骤 | 在哪操作 | 具体动作 | 验证标准 |
|---|------|---------|---------|---------|
| 1 | 统一账号 | 手机 + 电脑 | 确认两端登录**同一个账号**（邮箱区分大小写）；再去 App Store / 应用商店把手机 App 升到 **1.2.0 及以上** | 电脑端 WorkBuddy 帮助页显示版本 ≥ 5.3.8；手机 App 关于页 ≥ 1.2.0 |
| 2 | 建立设备连接 | 手机 App | 进入设备/连接列表，选择这台 Mac（`qydeMacBook-Air.local`）并**保持「连接电脑」模式开启**；允许查看在线/离线状态 | 手机端设备列表显示这台 Mac 为**在线 / 已连接**，而不是「离线」或「连接中」 |
| 3 | 指定工作空间 | 手机 App | 新建任务时，工作空间/分组**显式选中 `Documents/study`**（PC 端的任务与工作空间分组会同步到移动端） | 手机端任务列表出现 `study` 分组；在手机上追问旧任务，对话能在该空间续接 |
| 4 | 端到端实测 | 手机 | 发一条测试指令：「在 study 下新建 `测试-多端互通.md`，内容为一句话摘要」 | **立即在电脑 Finder 看到** `/Users/yang/Documents/study/测试-多端互通.md` 生成（不等同步、不等回传，即为成功） |
| 5 | 产物回传开关 | 手机 App 的 WorkBuddy 连接设置 | 打开「**产物回传到小程序**」开关 | 电脑端外的文件也能经 present_files 卡片发送到手机查看 |
| 6 | 落库确认 | 电脑 | 观察 `git -C ~/Documents/study status` | 新 md 出现在未跟踪列表；下一轮 automation（每 5 小时）自动 commit + push |

**第 4 步是唯一真正的验收点。** 前 3 步做得再漂亮，只要第 4 步的测试文件没有直接出现在 Mac 本地，就说明任务仍然跑在云端。

## 四、兜底路径（万一手机端暂时连不上电脑）

1. **GitHub 中转**：手机端生成的内容若是纯文本，直接粘贴进 GitHub 网页版 `Lummibunny/study` 新建文件；电脑端下一轮 automation 会自动 `pull`。
2. **手动归集**：把手机端的 md 通过任意方式传到 Mac，丢进 `~/Documents/study`，automation 会接管后续提交。
3. **微信通道**：完成扫码绑定后，微信里发指令给 WorkBuddy，等同于在本机发起任务（需电脑开机）。

## 五、排查清单

| 现象 | 检查项 |
|------|--------|
| 手机端看不到这台电脑 | 电脑是否开机、WorkBuddy 是否在运行、网络是否正常 |
| 任务列表不刷新 | 手机端下拉刷新；检查两端是否为同一账号 |
| 连接反复掉线 | 设备时间与服务器时区偏差是否超过 5 分钟（会导致令牌失效） |
| 仍不同步 | 到 Web 端「账户安全 → 已连接设备」撤销异常设备后重新登录 |
| 测试 md 没有出现在本地 | 说明仍在云端执行 → 回到步骤 2、3 检查连接与工作空间选择 |
