# 20 预约制的在线动态定价（精读）

> Mrkos J., Komenda A., Fiedler D., Vokřínek J. (2025). *IEEE Trans. Intelligent Transportation Systems* 26(9):13882–13897. 捷克技术大学（布拉格）。DOI: 10.1109/TITS.2025.3565906

## 一句话

把**预约 + 停车 + 充电打包成一个整体来定价**（bundle pricing），用**泊松过程**刻画预约到达，用 **MDP** 做在线动态定价，用**蒙特卡洛树搜索（MCTS）**做启发式求解。

## 技术链条（这条链我要记住）

```
泊松到达过程（预约请求，连续时间）
   ↓ 离散化成 k 个 timestep（引入误差，本文量化它：ε1 / ε2）
MDP（状态 s=(容量c, 时刻t, 请求产品p)；动作 = 报价 a；奖励 = 成交价）
   ↓
MCTS（UCT）启发式求解 —— 不用枚举全状态空间
```

还有一个细节亮点：论文专门分析了**"连续时间泊松过程塞进离散 MDP"的离散化误差**——这类"我做了近似，但我要证明近似可控"的写法，是 SCI 审稿人爱看的严谨性。

## 1. 研究背景与定位

- **场景**：高速公路沿线的**高需求快充站**（有限桩、需求可能超过供给）。作者刻意限定在**单个充电站**（local view），理由是集中式/全局方案在公共充电场景落地难。
- **为什么是"预约 + 打包"**：长途出行充电极其需要规划，若价格还不确定会更难。若充电可提前预约、**价格在预约时刻就锁定**，司机就能提前知道确切成本、规划整趟行程。
- **打包的内容**：交付电量 + 预约费 + 在场停留时间 + 停车位，**合成一个价格**（对现实中"连接费/停车费/空闲费"各自分收的显著简化）。
- **定价自由度**：fully dynamic —— 每个请求的报价都可以不同，取决于当前站状态、请求参数、对未来需求的预期。
- **目标**：单站运营商**收益最大化**（近年流行视角：没有盈利的充电站，电动化不可持续）。

### 文献坐标（作者的自我定位）
- 定价研究分 **centralized / decentralized**；本文走 decentralized。
- decentralized 又分 **global view**（博弈/拍卖，需多方共识、迭代协商，难落地） vs **local view**（单站视角，本文）。
- **预约**在 EV 充电业不常见（EVgo 有，提前 24h、固定费）；local 文献里也少。
- **动态定价**各家含义不同：有的定价"电价"（TOU 延伸）、有的定价"每分钟占用费"（激励充满即走）、有的定价"停车位预约"（Lei & Ouyang, Fang et al.）——**本文定价的是"整个预约充电服务"**，最接近 Fang et al.（但 Fang 是 1 小时步长广播式调价，本文是"客户来请求 → 站点回一个价"的协议）。

## 2. 问题形式化

**供给侧**：n 个资源（各时隙的充电容量）→ 组合成 m 个**产品**（一个充电会话 = 若干连续时隙，如 [1,1,0]）；初始容量 c0，各资源有售卖期 T（过期作废）。

**需求侧**：
- 到达：非齐次**复合泊松**计数过程 N(τ)，强度 λ（各产品的子过程合并而来，λ = Σλ_p）。
- 每个客户对产品有**隐藏的内心估值** b_i ∼ β_p（卖家不知道）。
- 客户**接受报价当且仅当** a ≤ b_i。

**交互协议**：① 客户在 τ_i 请求产品 p_i；② 若可行（未过期且容量足够）卖家报价 a，否则视为报无穷大（= 拒绝）；③ 客户比价，买或走。**拒绝动作 = a = ∞**（没人有无限预算），这个技巧很漂亮。

---

## 3. MDP 五元组（核心）

MDP = (S, T, R, A, s₀)

| 要素 | 定义 |
|---|---|
| **状态 S** | s = (c, t, p)：时刻 t 的剩余容量向量 c + 当前被请求的产品 p。把售卖期离散成 k 步 → 状态空间有限 |
| **动作 A** | 报价 a（有限离散价格集；也可连续，但现实服务商多用离散价）。**a = ∞ 即拒绝** |
| **奖励 R** | 客户接受则得 a，否则 0。（也可改成利润/利用率，取决于运营商目标） |
| **转移 T** | 由两部分决定：① **接受概率** p_acc(p,a) = P(X > a) = 1 − F_βp(a)（估值分布的补累积）；② **需求模型 D(t)**：离散化的泊松 → 多类 Bernoulli 过程（m+1 个结果，m 类请求 + 1 个"无请求"） |
| **策略 π** | (p, τ, c) → 报价 a |

**离散需求过程**（式3）：preq(p,t) = λ_p / k；P(无请求) = 1 − Σ_j λ_j/k。
**关键约束**：每个 timestep 最多 1 个请求；若现实中同一步到了多个，随机选一个先处理，第二个在同 timestep、可能已减少容量的状态下再报价 → 这是误差来源之一。

---

## 4. 离散化误差（本文最独特的贡献）

把连续泊松硬塞进离散 MDP 必然有误差。作者给了**两个误差指标**：

- **命题 1（收敛性）**：离散需求过程 D^k_λ(t) 在 k → ∞ 时收敛到复合泊松过程（强度 λ，跳跃分布 λ_i/λ）。证明要点：单产品 Bernoulli(λ_i/k) → 泊松(λ_i)；合并时"两个 Bernoulli 同时成功"的概率是 λ₁λ₂/k²，比各自成功概率 λ_i/k 更快趋于 0，所以极限仍对。
- **命题 2（误差量化）**：
  - **ε₁(k,λ) = k − (k+λ)e^(−λ/k)** —— 期望有多少个 timestep 里泊松实际来了 >1 个请求（离散模型却只允许 1 个）。
  - **ε₂(k,λ) = λe^(−λ/k) + (λ−k)(1−e^(−λ/k))** —— 因"忽略第 2 个及以后的到达"而**总共漏掉的到达数**。
- **实用口径**：用**相对误差 ε₂(k,λ)/λ**（每个期望请求漏掉多少个）来控制质量。实验中全程锁定在 **0.06**。
- 直觉：离散模型系统性地**低估"多到达"概率、高估"恰好一个"概率**；k 越大误差越小，但计算量越大 → 这就是**近似精度 vs 计算复杂度的权衡**，作者用实验把这个 tradeoff 显式做出来了。

## 5. 求解：MCTS（UCT）

- **为什么不用 RL**：作者明确避开强化学习（训练算力大 + 目前缺乏有代表性的真实数据），改成"**精简模型 + 可扩展启发式**"。
- **为什么不用 VI**：Value Iteration 状态空间是 k·c₀^n·n(n+1)/2，**随时隙数 n 指数爆炸**，只能跑小算例（实验中 >4 个资源就内存爆掉）。
- **MCTS 四阶段**：Selection（UCB1：q + c·√(ln n_s / n_{s,a})）→ Expansion → Value estimation（rollout）→ Backpropagation。
- **Rollout 加速**：到达间隔在离散化后服从**几何分布**，直接采样到下次到达 → 更快到终态。rollout 用均匀随机策略。
- **实现**：基于 POMDPs.jl；在"真实"MDP 各步之间**复用已建的决策树**加速收敛。
- **调参结论（很实用）**：网格搜索显示 **迭代次数 n_iter 对性能影响最大**，探索常数 c 和树深 d_max 影响很小；但 n_iter 和 d_max 最影响耗时。最终取 **n_iter = 10000, d_max = 10, c = 3**。

---

## 6. 数据与实验设置

- **真实数据**：德国某本地运营商**单站 1513 条充电会话、跨 2 年、平均时长 44 分钟**（含开始时间与时长），用来**拟合分布形状**（开始时间 ~ 正态、时长 ~ 指数）。
- **重要提醒**：该真实站是**低需求站**，而本文方法面向**高需求站**；所以实验里把需求参数**刻意调得远高于数据集**（高速公路多快充桩场景）。作者坦承：**低需求场景下这类动态定价收益不明显，不值得那套开销**。
- **用户预算分布**：没有真实数据 → **参数是任意设的**（诚实说明）。
- **到达**：离散化齐次泊松；非齐次（时变 λ）可通过时间轴变换等价处理，故用齐次不失一般性。
- **每配置跑 100 条请求序列取平均**。

### 三个基线（这套 baseline 设计值得抄）
| 基线 | 含义 | 角色 |
|---|---|---|
| **Flatrate** | 全站一个固定每分钟价（先用训练集搜最优固定价） | **下界**（现实中主流：按 kWh / 按小时的固定费率） |
| **Value Iteration (VI)** | MDP 最优策略 | MDP 模型内**最优**上界（状态空间指数爆炸，只跑小算例） |
| **Oracle** | 已知未来全部请求与客户预算，解一个 BIP | **不可达的理论上界** |

---

## 7. 主要结论

- **MCTS 明显优于 Flatrate，且紧追 VI 最优策略**（在 VI 能跑的小算例上），并且**可扩展到大算例**。
- **时隙粒度越细（timeslot 越短），所有方法收益都越好**；VI 在时隙短于 6 小时就内存爆掉，MCTS 不受影响。
- **需求越高，MCTS 相对 Flatrate 的优势越大**（动态定价的价值随稀缺性上升）。
- **机制解释**（Fig.12）：高需求下各策略几乎都把容量占满，但 MCTS/Oracle 能从**同样的请求里榨出更多收益**，或卖出 Flatrate 因过早耗尽容量而放弃的请求。
- MCTS 虽随机，但**没有显著增加结果方差**。
- 全程把离散化相对误差 ε₂/λ 锁在 0.06 → 证明"近似可控"。

## 8. 假设与局限（= 研究空白，对你最有用）

作者**明说自己没做**的：
1. **不处理预约的取消 / 修改（cancellations / modifications）**；
2. **不处理司机的策略性行为**（例如一个人预约多个会话但没打算全用）；
3. 假设司机按需要求时隙、准时或稍晚到、预约结束前离开 —— **不建模不准时/爽约（no-show）**；
4. 假设充电结束就走（高速站合理，**目的地桩不成立**，除非另加激励）；
5. 不建模功率曲线 / 电网可用性 / 电价变动（说可扩展，留作未来）；
6. 用户预算分布**无真实数据**（任意设定）。

**未来工作**（作者原话）：① 若有合适训练数据，在**真实数据**上评估（验证离散化误差的实际影响）；② 把"预约充电动态定价"与"司机行程多目标优化"结合，放进**多智能体仿真**，评估定价对**司机侧**和运营商侧的影响。

## 9. 与你选题的衔接

- 这是目前**唯一一篇把"预约"本身作为定价对象**的顶刊论文。你要做"日前预约 + 临时充电"，最自然的机制抓手就是**两类需求差别定价**——这篇给了全套工具（MDP 形式化 + 离散化误差论证 + baseline 阶梯）。
- **它明确不管"取消/改约/策略性行为/爽约"** —— 这几条恰恰是你"行为异质 + 机制设计"要补的缝。把它的"客户估值 b_i 是外生隐藏变量"改成"**司机会策略性虚报/会不准时**"，就是你的增量。
- 与 19 号（Huang Omega 2026，公交场站共享充电）对照：19 号是**确定/鲁棒优化的集中式调度**，本文是**随机到达下的在线定价**；一个管"怎么排"，一个管"怎么定价"。两者可以拼成"预约容量分配 + 价格引导"的完整机制。
- 与 12 号（在线菜单/IC）对照：本文是**卖家定价、客户被动接受或走**（posted price）；菜单机制是**给一组选项让客户自选**。从 posted price 升级到 menu/IC，正是机制设计味道更浓的一步。

## 10. 我的想法（回答占位里的三个问题）

**Q1：我的"临时充电"请求到达，是不是也能用泊松过程描述？**
能，而且这篇就是这么干的。作者还特意说明：**定价方法不依赖任何特定需求模型形式（除了"到达是泊松"这一条），且允许非齐次（时变）需求**。所以你的临时请求若有明显时段性，用**非齐次泊松**（分段常数 λ(t)）即可，作者证明通过时间轴变换可等价处理成齐次。你缺的是**真实数据的到达率 λ(t)** —— 这也是审稿人会问的点，建议尽早找一段真实的充电订单/到达记录来拟合。

**Q2：打包定价 vs 分开定价，在我的场景里哪个合理？**
本文主张 bundle，理由是长途/高速场景司机最怕**价格不确定**，提前锁定总价便于行程规划，且把连接费/停车费/空闲费全塞进一个价是对现实碎片化收费的**显著简化**。
但你的场景要分情况：**如果停车/占位资源本身紧张（比如站内车位有限、充满不走会堵桩），把"停车时长"也打包进去会诱导长占桩**。这时更合理的是**分开定价**（充电按 kWh/时长 + 占位/超时费）或"打包价 + 超时惩罚"。
→ 这可以直接做成你论文的一个**对比实验：bundle vs unbundled**，本文给的是 bundle 那一侧的建模模板。

**Q3：MCTS 我不会写怎么办？**
本文给了现成的**三档阶梯**，正好是你循序渐进的路线：
```
Flatrate（固定价规则，下界）  ← 先做这个，跑通 baseline
   ↓
MDP 框架搭起来 + 小算例用 VI 验证最优性
   ↓
MCTS（启发式，可扩展）        ← 最后再上，可用现成库（本文用 POMDPs.jl）
   ↓
Oracle（已知未来的 BIP，理论上界）
```
先把 MDP 框架和 Flatrate 跑通是对的。**调参优先级也已明确：n_iter（迭代次数）对性能影响最大，探索常数 c 和树深 d_max 影响很小** —— 所以你不用在 c 上死磕，把算力花在迭代次数上。

## 11. 一句话总结

一篇 IEEE T-ITS 2025 的标杆论文：**把"预约充电服务"整体打包定价，用泊松到达 + MDP 做在线动态定价，用 MCTS 求解，并专门量化了"连续泊松离散化"的近似误差**；它刻意**不管取消、改约、策略性行为和爽约**，这几条正是你"行为异质 + 机制设计"选题可以直接补进去的增量。
